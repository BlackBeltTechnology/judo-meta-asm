# `osgi-itest/src/test/java/hu/blackbelt/judo/meta/asm/osgi/itest` — Pax Exam / Karaf integration test proving the ASM OSGi bundle publishes `AsmModel` as a service

| File | Purpose |
|---|---|
| `AsmModelLoadITest.java` | Pax Exam test (`@RunWith(PaxExam.class)`, `@ExamReactorStrategy(PerClass.class)`) verifying `AsmModelBundleTracker` turns a model-carrying bundle into an injectable `AsmModel` service. `@Configuration config()` composes `KarafFeatureProvider.karafConfig(getClass())` with `guava` + `failureaccess`, the judo-zeta bundles (`...zeta.common`, `...zeta.annotations`, `...zeta.validation-core`), the `hu.blackbelt.judo.meta.asm.osgi` bundle, and a provisioned tinybundle. `getAsmModelBundle()` builds an in-memory model with one `EPackage` (`test`, nsURI `http://blackbelt.hu/judo/test/test`), serializes it via `SaveArguments.asmSaveArgumentsBuilder().outputStream(os)`, and packages it with header `Asm-Models: name=<name>;file=model/<name>-asm.model` — that header is the tracker contract under test. `@Inject AsmModel asmModel` therefore resolves only if the tracker parsed it. `testModelValidation` runs `AsmEpsilonValidator.validateAsm` against `calculateAsmValidationScriptURI()` inside the container, exercising the `jar:bundle:` branch of URI resolution. Uses JUnit 4, not JUnit 5 like the `model-test` suite. |
| `KarafFeatureProvider.java` | Shared Pax Exam harness building the Karaf container options; not a test. Exports `karafConfig(Class<?>)`, `configureVmOptions()`, `karafUrl()`, `getFreePort()`, `getKarafPort()`, `getConfigFile(Class<?>, String)`, `testTargetDir(Class<?>)`, `getOsgiService(...)` overloads, `findBundleByName`, `assertBundleStarted`, `waitWebPage`, `sleepOrTimeout`, `asCollection`, `explode(Dictionary)`, constants `KARAF_VERSION` = `4.3.3`, `SERVICE_TIMEOUT` = `30000`, `KARAF_GROUPID`/`APACHE_KARAF`/`ZIP`, `SERVICEMIX_BUNDLES_GROUPID`/`HAMCREST`. `karafConfig` unpacks into `target/exam`, forces `cleanCaches(true)`, replaces `etc/org.ops4j.pax.logging.cfg` from test resources, and installs feature `test` from `target/test-classes/test-features.xml` — that file must be filtered onto the test classpath or the container fails to provision. System properties steer it: `karafPort` (else a free port), `isDebugEnabled` (adds JDWP on `5005`, `suspend=y`), `useCustomSettings` (swaps in `etc/org.ops4j.pax.url.mvn.cfg`), `karafVersion` (patch-module jar names). `configureVmOptions` sets `pax.exam.osgi.unresolved.fail=true`, `-Xmx2048M`, headless AWT, plus the JDK9+ `--patch-module` / `--add-opens` / `--add-exports` set Karaf needs; dropping one of those breaks startup, not just a test. |
