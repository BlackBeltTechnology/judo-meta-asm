# `model/src/main/java/hu/blackbelt/judo/meta/asm/cli` — judo-cli-api service implementations binding ASM into the CLI

| File | Purpose |
|---|---|
| `AsmFqnResolverImpl.java` | Implements `FqnResolver` (model-cli-api) over an Ecore `ResourceSet`; `getModelType()` returns `asm`. Exports `bind(ResourceSet)` / `unbind()` / `isBound()`, `resolve(String fqn)`, `getFqn(EObject)`, `getFqnCollection()`, `findByPattern(String regex)`, `resolveByXmiId(String)`. `bind` eagerly walks `resourceSet.getAllContents()` and fills a `ConcurrentHashMap` FQN→`EObject` cache; the cache is NOT invalidated on model mutation, so callers must re-`bind` after changing the model. FQN forms delegate to `AsmUtils.getPackageFQName` / `getClassifierFQName` / `getAttributeFQName` / `getReferenceFQName` / `getOperationFQName`; enum literal uses `AsmUtils.FEATURE_SEPARATOR`, parameter uses `<opFqn>/<param>`, annotation uses `<containerFqn>@<lastSegmentOfSource>`, annotation detail uses `<annotationFqn>/<key>`, and anything else falls back to `EcoreUtil.getURI(...)`. `findByPattern` takes a Java regex via `String.matches`, not a glob. |
| `AsmValidatorImpl.java` | Implements `ModelValidator` (judo-cli-api) for model type `asm`; exports `getModelType()` and `validate(Logger, Object)`. Delegates to `AsmEpsilonValidator.validateAsm(logger, asmModel, AsmEpsilonValidator.calculateAsmValidationScriptURI())` — EVL path only, never the Java `AsmValidator`. Non-`AsmModel` argument throws `IllegalArgumentException`; any validation failure is wrapped as `CliValidationException("asm", ...)`. Zeta validation deliberately removed (JNG-6354) — do not reintroduce here. |
