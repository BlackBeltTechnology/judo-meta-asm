# `model/src/main/java/hu/blackbelt/judo/meta/asm/validation` — native Java (judo-zeta) validation path, parallel to the EVL path

| File | Purpose |
|---|---|
| `AsmModelProvider.java` | Adapts ASM traversal to judo-zeta; implements `ModelProvider` with `getAllContents(ResourceSet, Class<T>)`, delegating to `new AsmUtils(resourceSet).all(type)` and collecting to a `List`. Constructs a fresh `AsmUtils` per call, so it picks up the shared `AsmUtilsCache` for that `ResourceSet` — a stale cache after model mutation leaks into validation. Result is materialized, not lazy. |
| `AsmValidator.java` | Java-side counterpart to `AsmEpsilonValidator`. Exports static `validateAsm(Logger, AsmModel)`, `+ (expectedErrors, expectedWarnings)`, `+ (parallel)`. Wires the judo-zeta stack: `ValidationRegistry`, `ExtensionMethodRegistry`, `ValidationContext(new AsmModelProvider(), asmModel.getResourceSet(), extensionRegistry)`, `ValidationExecutor(registry, context, parallel)`, then partitions `ValidationResult`s by `Severity.ERROR` / `Severity.WARNING` and compares `getConstraintName()` sets against expectations. Registry is currently EMPTY — no rule class is registered, matching the empty `asm.evl`; new rules must be added at the `registry.register(...)` site or this validator silently passes everything. Contract: `expectedErrors` null means none expected, `expectedWarnings` null means warnings ignored; any unexpected or missing name throws `AsmModel.AsmValidationException`. Reports bare constraint names, unlike EVL's `ConstraintName|message` form — `AbstractAsmValidationTest` exists to bridge that. |
