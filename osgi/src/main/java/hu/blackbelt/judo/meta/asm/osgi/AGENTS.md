# `osgi/src/main/java/hu/blackbelt/judo/meta/asm/osgi` — OSGi component turning model-carrying bundles into `AsmModel` services

| File | Purpose |
|---|---|
| `AsmModelBundleTracker.java` | `@Component(immediate = true)` that watches bundles declaring manifest header `Asm-Models` (constant `ASM_MODELS`) and publishes each declared model as an `AsmModel` OSGi service. Exports `activate(ComponentContext)` / `deactivate(ComponentContext)`; requires an injected `BundleTrackerManager` (`@Reference`) and registers register/unregister `BundleCallback`s plus a `Predicate<Bundle>` keyed on `BundleUtil.hasHeader(bundle, "Asm-Models")`. Header entry contract: parameter `name` (`AsmModel.NAME`) is the registration key and `file` is the bundle-relative model path, e.g. `name=demo;file=model/demo-asm.model`; the model is loaded through `AsmModel.loadAsmModel(...inputStream(trackedBundle.getEntry(file).openStream()))` and registered with `asmModel.toDictionary()` as service properties, so `name`/`version`/`uri` become the service filter keys. Names must be globally unique — a duplicate `name` is logged as an error and the second model is silently NOT registered. `IOException` and `AsmValidationException` are caught and logged only, so a broken model yields a missing service rather than a bundle failure. `asmModelRegistrations` is a `ConcurrentHashMap` while `asmModels` is a plain `HashMap`; both callbacks return `null` from `process(Bundle)`, i.e. tracking work runs on the caller thread. |
